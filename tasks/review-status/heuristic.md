# Heuristic Review Status

**Last Updated:** 2026-07-07 20:19 ET

**Executive Summary:** The app's core generation workflow (Job → Analysis → Customise → Rewrites → Spell Check → Layout → Download) is well-instrumented — clear status pills, abort controls, staleness banners, and forward-skip confirmations. The newer post-generation tail (Cover Letter → Screening → Interview Prep → Thank You → Finalise → Update Master CV) is comparatively weak: the workflow bar falsely marks all six of these steps "completed" the instant final files are generated, and the just-completed "Harvest → Update Master CV" rename was applied to the nav/tab label but missed the tab's own page heading and several cross-references, leaving old and new terminology mixed. A second regression (the header "? Help" button silently losing its only path back to the onboarding guide) reduces discoverability of getting-started help for returning users.

## Top 5 UX Issues (friction/abandonment risk)

1. **Workflow bar shows false "completed" status for 6 steps the user never touched.** The moment `phase` reaches `final_generation`/`refinement`, `done.cover_letter`, `done.screening`, `done.interview_prep`, `done.thank_you`, `done.finalise`, and `done.harvest` are all set `true` regardless of actual per-tab progress (`web/workflow-steps.js:963-978`), rendering all six pills in success-green (`web/styles.css:304`). A returning user could reasonably believe they already sent a cover letter or answered screening questions when they have not. Backend has no phase concept for any of these six steps to ground the claim (`scripts/utils/conversation_manager.py:39-48`).

2. **The "Harvest → Update Master CV" rename is only half-applied, actively reintroducing the jargon it was meant to remove.** Nav pill and tab strip say "Update Master CV" (`web/workflow-steps.js:50`, `web/index.html:153,241`), but the tab's own page heading still reads "🌾 Harvest Improvements" in all 5 render paths including error/loading states (`web/harvest.js:284,309,366,380,386`), the Thank You tab's CTA still says "Proceed to Harvest Improvements →" (`web/thank-you.js:36`), and both the Skills tab and Master CV tab still tell users to go find "the Harvest tab" (`web/skills-review.js:1193`, `web/master-cv.js:328,1783`). The onboarding modal's "How it works" step 3 also still describes this as "Harvest improvements" (`web/index.html:366-369`). A user following any of these pointers lands on a tab whose own heading contradicts the label they clicked.

3. **The header "? Help" button silently lost its only path back to the getting-started guide.** `web/app.js:170-178` permanently removes the `onclick="showWelcomeModal()"` handler set in `web/index.html:64` and rebinds the button to the keyboard-shortcuts panel. `showWelcomeModal()` has no other caller anywhere in `web/*.js` (verified by search). Once a user checks "Don't show automatically on startup" (`web/index.html:413`), the getting-started guide becomes permanently unreachable from the UI.

4. **"Skip to Finalise" is visually coded as a minor/backward action but is actually a major forward jump past 4 steps.** It uses `.back-btn` (muted gray, same class used for genuine "go back" actions) while sitting next to `.continue-btn` (`web/download-tab.js:521-528`, `web/styles.css` `.back-btn`/`.continue-btn` definitions), even though clicking it bypasses Cover Letter, Screening, Interview Prep, and Thank You entirely. Users skimming by button color/weight may not register this as a consequential, workflow-skipping choice.

5. **"LLM" jargon survives outside index.html despite the header/chrome now saying "AI Model."** Visible (non-comment) strings in `web/harvest.js:272,286,333,369`, `web/cover-letter.js:233,307`, `web/job-analysis.js:106`, `web/screening-questions.js:237`, `web/skills-review.js:1057`, `web/experience-review.js:292`, `web/achievements-review.js:344`, and `web/spell-check.js:399` all say "LLM provider," "LLM recommendation," "LLM analysis," or "LLM defaults." This creates a jarring vocabulary split for non-technical job seekers between the rebranded chrome and the still-technical conversation/tooltip copy.

## Terminology and Labeling Findings

- **Harvest vs. Update Master CV (see Top Issues #2).** Concrete inventory of remaining "Harvest" user-facing strings: `web/harvest.js:284,309,366,380,386` (`<h1>🌾 Harvest Improvements</h1>`), `web/thank-you.js:36` ("Proceed to Harvest Improvements →"), `web/skills-review.js:1193` ("available for write-back to master CV in the Harvest tab"), `web/master-cv.js:328` ("The Harvest feature (Harvest tab) can add new ones..."), `web/master-cv.js:1783` ("Use the Harvest feature to add achievements..."), `web/index.html:368` (onboarding step-3 copy: "Harvest improvements"). None of these were touched by the GAP-367/368 cleanup, which only updated the workflow-step pill and tab-bar label (`web/workflow-steps.js:50`, `web/index.html:153,241`).
- **"Master CV" is overloaded.** The header/position-bar button "📚 Master CV" (`web/index.html:109-111`) opens the persistent-profile editor, while the renamed step "🌾/Update Master CV" (`web/index.html:153`) is the harvest-review-then-apply flow that *writes into* that same profile. Both are legitimately about "the Master CV" but are different mechanisms (direct manual edit vs. AI-scored candidate promotion); the shared phrase invites confusion about which one to use, especially now that the tab content itself still calls the latter "Harvest."
- **"Finalise" has three different labels for one action across surfaces:** the workflow pill says "Finalise" (`web/workflow-steps.js:955`), the tab content heading says "Finalise Application" (`web/finalise.js:79`), and the primary action button dynamically relabels itself to "Archive Application" at runtime (`web/app.js:158-161`, overriding the static "📦 Package Application Files" text baked into `web/index.html:205`). A user reading the button's initial HTML (before JS finishes wiring) briefly sees a third label ("Package Application Files") that never persists.
- **`domain_relevance` field (GAP-359) is explained only via a hover `title` tooltip, not visible inline text.** `web/master-cv.js:622-625` labels it "Domain Relevance (comma-separated)" with `title="Domains this experience is especially relevant to — improves domain-specific AI recommendations"`. The sibling `Tags` field (`web/master-cv.js:617-619`) has no such explanation at all, and neither field surfaces its guidance without a mouse hover — keyboard-only and touch users get the placeholder example ("e.g. pharma, clinical") but not the purpose. `MASTER_CV_DATA_SPECIFICATION.md:116` documents the field only as `array`, with no semantic description either, so the UI tooltip is currently the only explanation of this concept anywhere in the product.
- **Session notes indicator (GAP-352) verified working**: `web/session-actions.js:204-214` populates `#position-notes-indicator`/`#position-notes-text` from `status.notes`, matching the new `notes` field on `StatusResponse` (`scripts/web_app.py:137`). Long notes are truncated with `text-overflow:ellipsis` and only fully readable via the `title` attribute (`web/index.html:87-89`) — same hover-only-disclosure pattern as the `domain_relevance` field above.
- **Publication modal duplicate-id fix (GAP-309) verified resolved**: heading now uses `id="pub-modal-title-heading"` (`web/master-cv.js:359`) distinct from the Title *field* input `id="pub-modal-title"` (`web/master-cv.js:389`) — no more collision.
- **Skip-navigation link (GAP-346) verified present and functional**: `<a href="#document-content" class="skip-link">Skip to content</a>` is the first focusable element in `<body>` (`web/index.html:33`), with `.skip-link:focus` kept visible via dedicated CSS (`web/styles.css:168,181`) rather than a `.sr-only` pattern that would re-hide it.
